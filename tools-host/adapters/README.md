# Local host adapter boundaries

These modules use Node built-ins and must never enter a browser bundle. Host configuration supplies named absolute roots, exact native executable/argument profiles and Git author identity. Agent input cannot supply an executable, shell, arguments, environment, absolute root or Git configuration. The shared executor checks task ownership, capabilities, kind and explicit grants before calling an adapter. Adapters independently validate their inputs and root read/write policy.

- Filesystem tools support bounded UTF-8 reads and atomic file replacement in existing directories. They reject traversal, drive/UNC/device/ADS paths, known credential paths, symlink/junction components and multiply linked files. They have no delete, recursive directory or link-creation operation. Audit summaries contain operation, root alias, byte count and digest, not file bodies or paths.
- Terminal profiles are trusted host code. Use fixed harmless programs or host-owned fixtures; allowing interpreters, repository package scripts or plugin/config-driven validators under agent-writable roots defeats a command allowlist. Processes use `shell: false`, an absolute native executable, hidden windows, a minimal environment without inherited credentials or executable search paths, combined output limits and bounded lifetime. Abort/timeout/output overflow terminates the owned process tree and waits for child close. Nonzero exits produce `PROCESS_EXIT` with the exit code in its safe message; failed-process stdout/stderr are not published.
- Git roots must be standalone repositories at the exact configured top level. Linked/shared metadata, object alternates, external configuration includes, custom filters and promisor/partial-clone configuration are rejected. System/global config, hooks, fsmonitor, signing, pagers, prompting, external diff and textconv execution are disabled. Automatic maintenance, garbage collection and lazy fetch are disabled, and no transport protocol is allowed. Writes require a writable root and explicit selected files; commit requires exactly those staged files. Git operations sharing a root are serialized. There is no push, fetch, reset, checkout, clean, rebase or history-rewrite operation.

This is a bounded local capability layer, not an OS sandbox. Roots and executable profiles must be owned by the host, without concurrent adversarial filesystem/configuration mutation. Portable Node APIs cannot eliminate all path-validation/open/rename races. Another local process with filesystem authority can replace a directory between checks. Host-configured executable profiles also remain capable of effects beyond their working directory; they must be reviewed before registration. No browser transport may accept a new profile or root.

Cancellation cannot undo a filesystem rename or Git commit that already completed. The executor must retain cancelled/failed execution truth without claiming side effects were rolled back. A killed Git process can leave an index lock that requires explicit host recovery; no automatic deletion or destructive repair is performed. Runtime logs should retain only validated bounded public output and safe summaries, never environment values or credentials. Known credential filename rejection does not detect a secret hidden in an otherwise permitted file, so the development transport uses only disposable host-authored fixtures.
